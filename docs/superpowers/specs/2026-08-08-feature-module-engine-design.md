# Feature-Module Engine — Design

**Date:** 2026-08-08
**Status:** Approved (design phase)
**Repo:** react-app-generator (Forge-Stack-Workshop)

## Problem

The template ships only three toggleable features (i18n, theming, mock). Each is
implemented as inline conditionals scattered across a 1488-line `scaffold.mjs`, with
component code embedded as JavaScript template strings. This does not scale: adding
"many common features" means more scattered `config.features.some(...)` branches in one
monolith, and the emitted code is never linted or tested as real source.

**Goal:** ship a growing catalog of common features, selected via a committed config
file, emitting only the selected code — and let a re-run **sync** an existing generated
project to an edited config (add and remove features in place) without clobbering the
user's own edits.

## Non-goals

- Not a general plugin marketplace or remote feature registry. Features are local
  folders in this repo.
- Not a runtime feature-flag system. Selection happens at generation/sync time.
- Not preserving user edits **inside** a feature's owned files across a disable+re-enable
  (a removed feature's owned files are deleted; re-enabling regenerates them fresh).

## Architecture

### Feature module (real files on disk)

```
templates/
  base/                       # always-emitted skeleton — real .tsx/.scss/.ts files
    src/...
  features/
    <id>/
      feature.yaml            # manifest: name, description, default, deps, devDeps, options, contributes{}
      files/                  # copied verbatim (with {{token}} substitution) into the project
        src/<owned-paths>/...
```

- Base app source moves out of `scaffold.mjs` string builders into `templates/base/`.
- Each feature owns its paths **exclusively** (e.g. `src/features/<id>/`, `src/auth/`).
  Because paths are owned, **add = copy folder, remove = delete folder** — unambiguous.

### `feature.yaml` manifest

```yaml
id: auth
name: Auth + route guards
description: Login page, token storage, protected routes, useAuth, 401 handling.
default: false
deps:
  - zod@^3.23.8
devDeps: []
options: {}          # feature-specific, e.g. i18n languages
contributes:
  routes:
    - { path: /login, import: "./features/auth/LoginPage", component: LoginPage, guard: false }
  nav: []
  providers:
    - { import: "./features/auth/AuthProvider", component: AuthProvider }
  http:                # optional: HTTP-layer hooks (see Injection)
    - responseErrorHandler: "./features/auth/onUnauthorized"
```

`deps`/`devDeps` reuse the existing `name@range` string form already parsed by
`splitPackage()`.

### Shared wiring = tool-owned aggregators (never hand-edited)

Features never edit shared files directly. Instead the engine regenerates a fixed set of
aggregator files on **every** sync from the enabled set's `contributes`:

| Generated file                        | Built from              | Consumed by (base, hand-written) |
| ------------------------------------- | ----------------------- | -------------------------------- |
| `src/app/routes.generated.tsx`        | `contributes.routes`    | the router in `templates/base`   |
| `src/app/nav.generated.ts`            | `contributes.nav`       | the sidebar/header nav           |
| `src/app/providers.generated.tsx`     | `contributes.providers` | `main.tsx` provider tree         |
| `src/api/http/hooks.generated.ts`     | `contributes.http`      | the base HTTP client             |

An aggregator whose contribution set is empty is still generated (as an inert
pass-through) so the base app's imports always resolve.

Each `*.generated.*` file carries a header banner:
`// AUTO-GENERATED by scaffold.mjs — do not edit. Managed by forge.config.yaml.`
The base app imports each aggregator exactly once. User edits live only in
non-generated files, so a sync that rewrites aggregators cannot destroy user code.

The `http` contribution is realized by the aggregator too: the base HTTP client imports
a generated `src/api/http/hooks.generated.ts` that wires enabled features' request/
response handlers. This keeps `api/http/client.ts` hand-written and stable.

### `forge.config.yaml` (committed in the generated project)

```yaml
project: myapp
packageManager: pnpm
features:
  i18n: { languages: [fr, en] }
  theming: true
  mock: true
  auth: true
  dataTable: false
```

- A feature value of `true`/`false` toggles it; an object both enables it and supplies
  `options`. Absent key = disabled.
- Interactive CLI (first scaffold) writes this file. Editing it + re-running syncs.

### State lockfile `.forge/state.json`

Records, per applied feature: the exact list of files the engine wrote and a content
hash of each. Purpose:

- Clean removal: delete precisely what was written, even if the manifest later changes.
- Edit detection: on remove, if an owned file's current hash ≠ recorded hash, the user
  edited it → warn and require `--force` before deleting.
- Dependency ownership: records which deps each feature contributed, so reconciliation
  removes a dep only when no still-enabled feature (or base) owns it.

## Sync algorithm

```
1. Resolve config:
   - if interactive run: prompt, then WRITE forge.config.yaml
   - else: READ forge.config.yaml
   - validate every feature id against templates/features/*; unknown id => error listing valid ids
2. Load .forge/state.json (empty if first run) => applied set P (+ files, hashes, dep ownership)
3. enabled set E := features truthy in config
4. For f in (E \ P):   copy templates/features/<f>/files/** with {{token}} substitution => record in state
5. For f in (P \ E):   for each recorded file: if hash matches, delete; else warn (need --force); then drop from state
6. Regenerate ALL aggregators (routes/nav/providers/http) from E
7. Reconcile package.json:
     desired := base deps ∪ (deps of each f in E)
     add missing desired; remove deps owned ONLY by features in (P \ E); never touch unowned/user deps
8. Write .forge/state.json
9. If packageManager lockfile exists, print "run <pm> install" reminder (engine does not run installs)
```

Idempotent: running twice with the same config is a no-op (hashes match, aggregators
byte-identical).

## scaffold.mjs rework

Split the monolith into focused modules (each a file, single purpose):

| Module                    | Responsibility                                             |
| ------------------------- | ---------------------------------------------------------- |
| `tools/scaffold/yaml.mjs` | the existing minimal YAML parser (extracted)               |
| `tools/scaffold/config.mjs` | read/write/validate `forge.config.yaml`, interactive prompts |
| `tools/scaffold/render.mjs` | `{{token}}` substitution + file copy                     |
| `tools/scaffold/aggregate.mjs` | build the `*.generated.*` files from `contributes`     |
| `tools/scaffold/sync.mjs` | the sync algorithm + `.forge/state.json`                   |
| `tools/scaffold/deps.mjs` | package.json dependency reconciliation                     |
| `scaffold.mjs`            | thin CLI entrypoint wiring the above                       |

Constraints preserved: **zero runtime dependencies** (plain Node, no template-engine
package) — `{{token}}` is a regex replace; YAML uses the existing parser. Token set is
small and explicit: `{{projectName}}`, `{{apiBaseUrl}}`, `{{timeout}}`, plus per-feature
option tokens.

## Seed catalog (this spec)

Convert existing to modules: **i18n**, **theming**, **mock**.
Build new, one per injection vector:

| Feature             | Proves                                             |
| ------------------- | -------------------------------------------------- |
| auth + route guards | route injection + HTTP-layer injection + options   |
| data table          | self-contained component + dep merge (no wiring)   |
| toasts + ErrorBoundary | provider injection into the providers aggregator |
| forms + validation  | dep-heavy feature, no wiring                        |

## Error handling

- Unknown feature id in config → hard error, list valid ids, exit non-zero.
- Owned file edited before removal (hash mismatch) → warn, skip delete unless `--force`.
- Aggregator target directory missing (corrupted project) → recreate from `templates/base`.
- `forge.config.yaml` malformed → error with line context from the YAML parser.
- Sync never runs a package-manager install; it only reconciles `package.json` and prints
  a reminder.

## Testing (Vitest — uses the coverage setup added in this branch)

- **Engine unit tests:** enable→files present; disable→files gone; disable of edited file
  →blocked without `--force`; dep reconciliation add/remove; unknown id→error.
- **Aggregator tests:** given a `contributes` set, generated files match golden snapshots.
- **Idempotency test:** sync twice → second run produces zero changes.
- **End-to-end:** generate a project with a fixture config into a temp dir, assert file
  tree + `package.json` deps; then flip two features and assert the diff.
- Coverage floor 85% (as configured) for `tools/scaffold/**`.

## Phasing

1. **Engine:** config + render + aggregate + sync + deps + state, with tests.
2. **Convert** i18n / theming / mock to modules (regression: generated output equivalent
   to today's for the same selection).
3. **Seed features:** auth, data-table, toasts+ErrorBoundary, forms.

One coherent subsystem; ships in that order. Later features are additive folders +
`feature.yaml` entries, no engine changes.
